# 07 — Languages (Batch 3, 10 Nov 2026)

Decision: D-019. Code: `frontend/src/i18n/`. Review list for native readers: `docs/i18n/REVIEW.md`.

## How it works
- `LanguageProvider` holds `lang` (`en`, `ur`, `ur-Latn`), sets `<html lang dir>`, loads the Urdu font
  for Urdu, and offers `t`, `te` (errors), `formatDate`, `formatNumber`.
- `t('auth.login.title')`, `t('find.found', { count: 3 })` (plural via `Intl.PluralRules`), `{name}`
  placeholders, `**bold**` rendered by `<Rich>` (no HTML from dictionaries).
- Errors: the API returns `{ code, params, message }`; `te()` shows `errors.<CODE>` in the chosen
  language, with the field name translated from `fields.<key>`. Client checks return dictionary keys.
  Errors are stored as keys/descriptors and translated when shown, so switching the language also
  changes errors already on the screen.
- Dates: `Intl.DateTimeFormat` with `en-PK` / `ur-PK`; numbers and dates always use Western digits.
- First visit: `LanguageChooser` (three cards, each in its own language). Header, hero and footer have a
  `LanguageSwitcher`. The switch re-renders in place: no reload, typed form input stays.
- Storage: `localStorage['dlm.language']` (try/catch) for visitors; `User.preferredLanguage` for
  logged-in users (rule for which wins after login: D-019).
- Bundle: English is part of the main bundle; Urdu (13.8 kB gzip) and Roman Urdu (12.6 kB gzip) are loaded
  on demand.

## Adding or changing a text
1. Add the key to `en.js`, then to `ur.js` and `ur-Latn.js` (the tests fail if a key is missing or extra,
   or if a `{placeholder}` differs).
2. New server error: add the code to `backend/errors/catalog.js`, to `docs/API.md` (a test checks it), and
   to the three dictionaries (a test checks it).
3. Run `node scripts/i18n-review.mjs` in `.\frontend` to refresh `docs/i18n/REVIEW.md`.
