# Code review, November 2026 (Batch 4)

Reviewer: Claude Code, 11 Nov 2026, branch `feature/modules-1-3`. Scope: all backend and frontend source
files (422 files; list in the appendix). Every finding has a severity, the place, the problem, the fix and
the test that now proves it. Results of the full test runs are in the Batch 4 report.

## How the review was done (honest scope)

1. **Automated scans over every file:** user text turned into a regular expression; raw error messages
   in responses; `console.log` in server code; hard-coded colours in CSS; missing indexes for the queries
   that exist; routes without `protect` / `requireRole` / `validate`; `npm audit`, `npm outdated` and the
   licences of every installed package.
2. **Line-by-line reading** of every file added or changed in Batch 4 (238 files, marked in the appendix),
   and of every route file and controller (authorisation and ownership on each protected route).
3. **Targeted reading** of the older files where a scan pointed, plus the Batch 3 review fixes.
4. **Tests as evidence:** a finding counts as fixed only when a test fails without the fix.

Unchanged older files that no scan flagged were not re-read line by line in this batch (they were reviewed
in Batches 1–3 and are covered by their tests); this is stated so nobody over-reads the word "every".

## Other checks

- **Data integrity:** unique indexes for email, worker ID, CNIC hash (partial), audit `seq`, saved workers
  `{ customer, profile }`, evidence `{ worker, skillId, sha256 }`; conditional updates for identity, evidence and
  suspension decisions (409 on a race); `approvedEvidenceCount` kept in step by a save hook and by every
  evidence recompute. No multi-document transactions are needed: each decision changes one document, and
  the audit entry is written after it (a failed audit write returns 500 and the decision is visible in the
  next check of the queue).
- **i18n:** every new text is in the three dictionaries (1,300+ keys, same keys tested); new components use
  logical CSS properties; RTL tested in Urdu (help centre, landing, onboarding, admin pages in e2e axe).
- **Theme tokens:** colours in components come from tokens; the only literal colours are the validated
  chart palette (`components/charts/viz.module.css`, documented), print styles, and mask/shadow channels.
- **Maintainability:** shared helpers instead of copies (`features/navigation/destinations.js` for the 404
  search and the palette; `features/admin/adminHelpers.js`; `utils/masks.js`); new modules are small
  (largest new page `pages/admin/AdminUsers.jsx`, about 260 lines).
- **Licences:** backend direct dependencies MIT, BSD, Apache-2.0; all installed packages MIT / ISC / BSD /
  Apache / MPL-2.0 / BlueOak / 0BSD / CC0, plus `@img/sharp-libvips` (LGPL-3.0-or-later, dynamically linked by
  sharp, allowed for use) and `busboy` / `streamsearch` (MIT in their licence files; no `license` field in
  `package.json`). Frontend fonts are OFL-1.1.
